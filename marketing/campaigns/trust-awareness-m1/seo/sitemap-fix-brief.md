## 1. The Problem

### What is happening

The current sitemap at `https://mottars.com/sitemap.xml` contains **94 URLs that all use the wrong domain**: `mottars.ng` instead of `mottars.com`.

**Current sitemap URLs look like this:**
```xml
<url>
  <loc>https://mottars.ng/cars/toyota-camry-2025-1</loc>
</url>
```

**They should look like this:**
```xml
<url>
  <loc>https://mottars.com/cars/toyota-camry-2025-1</loc>
</url>
```

### Impact

- Google discovers 94 URLs from the sitemap, tries to crawl `mottars.ng`, gets an error (domain likely does not resolve or redirects), and **rejects every single URL**
- Zero pages are being indexed via sitemap discovery
- This is the single biggest blocker for all SEO progress
- Our current SEO score is 38/100; fixing this alone should push us toward 50+

### Additional issues in the current sitemap

1. **XML encoding errors**: Image URLs contain bare `&` characters instead of `&amp;`
2. **Missing blog URLs**: All 9 published blog posts are absent from the sitemap
3. **Auth pages included**: `/login` and `/register` are in the sitemap (should never be indexed)
4. **Junk listings included**: 5 test/faker car listings with nonsensical data are in the sitemap

## 2. Root Cause Analysis

The sitemap is almost certainly auto-generated by **next-sitemap** (or a similar Next.js sitemap generation package). The wrong domain comes from one of these sources:

### Most likely: Environment variable

```bash
# .env or .env.production
SITE_URL=https://mottars.ng        # <-- THIS IS THE BUG
# or
NEXT_PUBLIC_SITE_URL=https://mottars.ng
```

### Alternative: next-sitemap config

```js
// next-sitemap.config.js
module.exports = {
  siteUrl: 'https://mottars.ng',   // <-- THIS IS THE BUG
  generateRobotsTxt: true,
  // ...
}
```

### Alternative: Next.js metadata config

```ts
// next.config.js or app/layout.tsx
const config = {
  metadataBase: new URL('https://mottars.ng'),  // <-- THIS IS THE BUG
}
```

### How to find it

Run these commands in the project root to locate the source:

```bash
# Search for mottars.ng across all files
grep -r "mottars.ng" --include="*.{js,ts,tsx,json,env,mjs,cjs}" .

# Search for SITE_URL environment variable
grep -r "SITE_URL" --include="*.{js,ts,tsx,env,env.*}" .

# Search for siteUrl in config files
grep -r "siteUrl" --include="*.{js,ts,mjs,cjs}" .

# Check environment files
cat .env .env.production .env.local 2>/dev/null | grep -i "url\|domain\|site"
```

## 3. The Fix: Step-by-Step

### Step 3.1: Fix the domain source

**Find the file** using the search commands above. Then change the domain:

#### If it is in an `.env` file:

```bash
# BEFORE (broken)
SITE_URL=https://mottars.ng

# AFTER (fixed)
SITE_URL=https://mottars.com
```

#### If it is in `next-sitemap.config.js`:

```js
// BEFORE (broken)
module.exports = {
  siteUrl: 'https://mottars.ng',
  generateRobotsTxt: true,
}

// AFTER (fixed)
module.exports = {
  siteUrl: process.env.SITE_URL || 'https://mottars.com',
  generateRobotsTxt: true,
  exclude: ['/login', '/register'],  // Add this line
}
```

#### If it is in Next.js metadata (app/layout.tsx):

```ts
// BEFORE (broken)
export const metadata = {
  metadataBase: new URL('https://mottars.ng'),
}

// AFTER (fixed)
export const metadata = {
  metadataBase: new URL('https://mottars.com'),
}
```

### Step 3.2: Exclude authentication pages from sitemap

Add `/login` and `/register` to the sitemap exclusion list:

#### In `next-sitemap.config.js`:

```js
module.exports = {
  siteUrl: process.env.SITE_URL || 'https://mottars.com',
  generateRobotsTxt: true,
  exclude: ['/login', '/register'],
}
```

#### Additionally, add noindex meta tags to both pages:

In `app/login/page.tsx` (or equivalent):
```tsx
export const metadata = {
  robots: {
    index: false,
    follow: false,
  },
}
```

In `app/register/page.tsx` (or equivalent):
```tsx
export const metadata = {
  robots: {
    index: false,
    follow: false,
  },
}
```

### Step 3.3: Ensure blog URLs are included

Blog posts may be excluded from auto-generation if they use a CMS or dynamic routing that the sitemap generator does not discover. Check:

1. **If using `next-sitemap` with `getServerSideSitemapLegacy` or `getServerSideSitemap`**: Ensure the blog API/database query includes all published posts.

2. **If blog URLs are not auto-discovered**, add them as `additionalPaths` in the config:

```js

  siteUrl: process.env.SITE_URL || 'https://mottars.com',
  generateRobotsTxt: true,
  exclude: ['/login', '/register'],
  additionalPaths: async (config) => {
    const blogPaths = [
      '/blog',
      '/blog/best-cars-for-nigerian-roads-top-reliable-vehicles-in-2025',
      '/blog/buying-cars-in-nigeria-everything-you-need-to-know-in-2025',
      '/blog/car-inspection-checklist-what-to-check-before-buying-any-vehicle',
      '/blog/complete-car-buying-guide-what-to-look-for-when-buying-a-used-car-in-nigeria',
      '/blog/how-to-sign-up-on-mottars-complete-step-by-step-guide',
      '/blog/how-to-upload-your-first-car-listing-on-mottars',
      '/blog/understanding-mottars-features-messaging-offers-and-more',
      '/blog/used-cars-for-sale-in-nigeria-how-to-find-quality-vehicles-at-great-prices',
    ];
    return blogPaths.map((path) => ({
      loc: path,
      lastmod: new Date().toISOString(),
    }));
  },
}
```

### Step 3.4: Update robots.txt sitemap reference

If `robots.txt` is auto-generated by next-sitemap, it should automatically use the correct domain after Step 3.1. Verify the output contains:

```
Sitemap: https://mottars.com/sitemap.xml
```

If robots.txt is a static file in `/public/robots.txt`, update it manually:

```txt
User-agent: *
Allow: /
Sitemap: https://mottars.com/sitemap.xml
```

## 5. XML Encoding Fixes

### The Problem

Several image URLs in the sitemap contain Unsplash query parameters with bare `&` characters. In XML, `&` is a reserved character and MUST be encoded as `&amp;`.

### How This Manifests

```xml
<!-- BROKEN: bare & in URL causes XML parse error -->
<image:loc>https://images.unsplash.com/photo?q=80&w=1227&auto=format</image:loc>

<!-- FIXED: properly encoded -->
<image:loc>https://images.unsplash.com/photo?q=80&amp;w=1227&amp;auto=format</image:loc>
```

### Where to Fix

This is likely happening in the code that generates image entries in the sitemap. Look for where car listing images are fetched and inserted into the XML.

**If using next-sitemap with custom transform:**

```js
// The transform function should handle encoding automatically.
// If building XML manually, use a proper XML serializer or encode manually:

function escapeXml(url) {
  return url.replace(/&/g, '&amp;');
}
```

**If the sitemap XML is built with template literals:**

```js
// BEFORE (broken)
const imageEntry = `<image:loc>${imageUrl}</image:loc>`;

// AFTER (fixed)
const imageEntry = `<image:loc>${imageUrl.replace(/&/g, '&amp;')}</image:loc>`;
```

**Better approach** -- use an XML library like `xmlbuilder2` that handles encoding automatically:

```js
const { create } = require('xmlbuilder2');
// xmlbuilder2 will automatically escape & to &amp;
```

### Affected URLs (examples)

These Unsplash image URLs all contain `&` characters that need encoding:

```
https://images.unsplash.com/photo-1621979787123-daf3ba3187e2?q=80&w=1227&auto=format&fit=crop&ixlib=rb-4.1.0&ixid=M3wxMjA3fDB8MHxwaG90by1wYWdlfHx8fGVufDB8fHx8fA%3D%3D
https://images.unsplash.com/photo-1596123671126-0173cacc37d9?q=80&w=1635&auto=format&fit=crop&ixlib=rb-4.1.0&ixid=M3wxMjA3fDB8MHxwaG90by1wYWdlfHx8fGVufDB8fHx8fA%3D%3D
https://images.unsplash.com/photo-1708226633190-d5b9fe523b24?q=80&w=4033&auto=format&fit=crop&ixlib=rb-4.1.0&ixid=M3wxMjA3fDB8MHxwaG90by1wYWdlfHx8fGVufDB8fHx8fA%3D%3D
```

**All image URLs with query parameters must have `&` encoded as `&amp;` in the XML output.**
